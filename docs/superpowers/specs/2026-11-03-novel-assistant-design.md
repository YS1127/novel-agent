# 本地小说创作助手首版设计

## 意图与范围

面向单人、在本机浏览器中使用的中文中短篇小说创作助手。创作者能保存并切换多篇作品，从点子出发，经 AI 追问、方案与大纲确认、正文初稿、片段改写、手动编辑，最后导出 Markdown 或纯文本。每一步由创作者决定是否继续或采纳 AI 的建议。

首版不提供登录、多人协作、云同步、复杂版本历史或自动发布。AI 输出必须可检查和修改；不得让模型自动覆盖创作者写过的正文。服务默认只监听本机。

## 实施路径

考虑了两种顺序：

1. **按用户流程逐段交付**：作品管理 → 构思 → 正文 → 改写与导出。每段均能在页面中使用，便于尽早发现数据与交互问题；需要较早确定跨阶段数据结构。
2. **先集中完成 AI 写作链路**：能较快验证模型效果，但作品保存、确认与编辑边界会较晚落实，容易形成一次性演示。

创作者选择路径 1。实现以现有 Java 21、Spring Boot 3.5.16、MyBatis-Plus 3.5.17、MySQL、Vue 3、Vite 7、TypeScript 工程为基础。Redis 暂无明确缓存或协调需求，首版不接入。使用版本化迁移管理 MySQL 表结构。OpenAI 兼容接口直接通过有超时的 HTTP 客户端调用，不添加 Spring AI Alibaba；后续若需要供应商特性再评估。

## 页面与流程

主页面左侧是作品列表和新建入口，右侧是当前作品的阶段内容。新建时填写标题、点子、文风说明；列表按最近修改时间排序，切换作品不会混合内容。保存成功与失败都给出明确反馈。

构思阶段先显示 AI 提出的少量关键问题。首版以最多 3 个问题为默认，创作者可回答后生成故事方案和大纲，也可跳过不想回答的问题。方案和大纲都是可编辑文本。点击确认后才开放正文生成；修改已确认内容会要求再次确认。AI 返回异常或内容不符合格式时保留现有数据并提示重试。

正文阶段显示可手动编辑的长文本。生成初稿前显示将使用的已确认大纲；生成结果先作为候选内容，创作者明确采纳后才替换正文。对已存在的手动修改不得由重试静默覆盖。片段改写接收当前选中的文本和修改要求，返回候选片段；创作者可对比、采纳或放弃。若采纳前正文已变化，必须重新选择片段，避免替换错误位置。

导出使用当前已保存正文。Markdown 包含标题与正文；纯文本包含标题和正文，不附加内部状态或 AI 配置。文件名由作品标题安全化，空标题使用默认名。

## 数据与接口

MySQL 中以作品为聚合根保存标题、点子、文风、阶段、故事方案、大纲、正文、更新时间和乐观锁版本。追问和回答、改写候选分别存独立表，均关联作品。业务 Service 负责阶段校验、保存与事务；Controller 只处理 HTTP、DTO 校验和响应。列表分页，按更新时间降序、ID 降序稳定排序。冲突返回 409；输入错误返回 400；不存在返回 404；AI 服务失败返回 502，响应不泄露密钥或堆栈。

前端 API 模块集中封装请求，显示加载、空状态和失败状态。保存与 AI 操作分开，AI 请求期间保留当前编辑内容。正文编辑在显式保存时写入数据库，离开未保存内容前给出提示。

## AI 配置与密钥

创作者可在设置页填写 OpenAI 兼容服务地址、模型名称和 API Key。地址、模型可持久化；API Key 只在提交时发送，后续读取设置不回传明文。持久化密钥使用 AES-GCM 加密，主密钥存于本机 `.env` 中的 `AI_CONFIG_ENCRYPTION_KEY`；现有 `AI_API_KEY` 可作为未在页面保存密钥时的本机回退配置。没有主密钥时禁止通过页面持久化新 API Key，并明确提示。AI 请求设置连接和响应超时，失败不修改作品。服务地址只允许 HTTPS，或开发者明确配置的本机 HTTP 地址。

## 验收与验证

用可控 AI 替身验证追问、方案、大纲、正文与改写的成功和失败路径；用 MySQL 集成测试验证作品隔离、分页排序、乐观锁与迁移加载；用前端构建和关键交互检查验证页面状态。最后以本机 MySQL、Redis（仅检查配置，不要求参与首版业务）和用户提供的兼容服务配置做端到端手动检查。AI 模型输出质量属于人工验收，不以单元测试断言具体文风。

## 留给实现的选择

页面视觉样式、AI 提示词措辞、正文默认长度和重试按钮文案由实现阶段确定，并在 README 记录。首版默认生成中短篇初稿，提示模型控制长度；不对模型输出长度作硬性截断。
